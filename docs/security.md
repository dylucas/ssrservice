# 安全说明

## 设计假设

sspanel 面向**单机、自托管、个人或小团队**场景。它不是多租户平台，也不提供计费、审计合规模块。默认配置以“最小暴露面”为目标。

## 面板

| 项目 | 默认行为 |
|---|---|
| 监听地址 | `127.0.0.1:2096`，不直接对公网开放 |
| 密码存储 | bcrypt（cost 12），不存明文 |
| 初始密码 | 随机 16 位，仅打印一次，强制首次登录修改 |
| 会话 | HMAC-SHA256 签名的 `HttpOnly` Cookie，`SameSite=Strict`，HTTPS 时 `Secure` |
| 会话失效 | 修改密码后旧会话自动失效（会话版本绑定密码哈希） |
| 登录限流 | 默认 5 次失败/分钟/IP |
| 两步验证（TOTP） | 默认关闭，管理员可在「系统设置」中自行启用；RFC 6238，SHA-1、6 位、30 秒步长，允许 ±1 个时间步（共 90 秒窗口）。启用后登录分两步，第二步接受 6 位验证码或一次性恢复码 |
| 恢复码 | 10 个，每个 12 位 base32（60 bit）；只存 SHA-256 哈希，单次使用，仅在启用或重生成时显示一次 |
| 两步验证防重放 | 数据库记录已接受的最大时间步，同一验证码不能重复使用；恢复码消费是原子操作，只有一个请求能成功 |
| 2FA 敏感操作 | 绑定、关闭与重生成恢复码都要求输入当前密码，防止会话被劫持后攻击者绑定自己的验证器；完成绑定只需待绑定密钥对应的验证码 |
| 登录第二步限流 | 与密码步共用既有按 IP 限流（默认 5 次/分钟）；密码步成功不重置失败计数，只有完整登录成功才清空（否则知道密码者可反复重置预算来穷举 6 位验证码）；面板仍不应直接暴露公网 |
| CSRF | 变更请求校验 `Origin` 同源；Cookie 为 SameSite=Strict |
| 响应头 | CSP、`X-Frame-Options: DENY`、`nosniff`、`Referrer-Policy: no-referrer`，HTTPS 时 HSTS |
| 请求体上限 | `/api/v1` JSON 请求体限制 1 MiB，超出返回 `413 payload_too_large`；建议反代再加 `client_max_body_size 2m` |
| 压缩 | 压缩内嵌静态资源（`Accept-Encoding: gzip`），以及不含凭据的用户列表端点（`GET /clients`、`GET /inbounds/:id/clients`，响应体 ≥ 4 KiB 时）。含 PSK、订阅 token 的其余 API 响应不压缩，避免同连接压缩秘密带来的 BREACH 类风险 |
| API 缓存 | `/api/v1` 响应统一带 `Cache-Control: no-store` 与 `Pragma: no-cache`，避免浏览器或中间缓存留存含 PSK、订阅 token 的响应 |
| 批量接口 | 用户列表只返回摘要，不含 `psk`/`sub_token`/`link`，凭据只在单个用户端点返回，减少秘密在批量响应中的暴露面 |
| 日志 | `password`/`psk`/`token` 不写入日志；`/sub/<token>` 路径脱敏，子路径部署（`base_path: /panel`）同样脱敏为 `/panel/sub/<redacted>` |
| 审计 | 写操作与登录记录到 `audit_logs`，只存固定的 `key=value` 摘要，不含密码、用户/服务器 PSK、订阅 token；保留 90 天且最多 5 万条 |
| 两步验证审计 | 启用、关闭与重生成恢复码记为 `admin.totp.enable`、`admin.totp.disable`、`admin.totp.recovery`；登录第二步失败记 `auth.login.failed` 并带 `stage=totp`；审计与日志不含密钥、验证码、恢复码 |
| 导出 | 用户 CSV 导出**包含 PSK**（否则无法恢复用户），与单个用户详情同权限，响应 `no-store`；导出文件请按凭证保管 |

建议：

- 远程管理使用 SSH 隧道，或把面板放在 TLS 反代之后，并限制来源 IP。
- `panel.trusted_proxies` 默认为空，表示**不信任任何** `X-Forwarded-*` 头。只有把它设置为反向代理的地址（IP 或 CIDR）后，面板才会采用 `X-Forwarded-For` 作为真实客户端 IP，并在 `X-Forwarded-Proto: https` 时设置 `Secure` Cookie 与 HSTS。否则客户端可以伪造这些头绕过登录限流或污染日志。
- 首次登录立即改密，之后定期轮换。
- 启用两步验证后仍应通过 SSH 隧道或 TLS 反代访问面板，并妥善保存恢复码；设备与恢复码全部丢失时，可在服务器上执行 `sspanel admin reset-totp` 清除两步验证（需要文件访问权限，`reset-password` 不会清除）。
- 面板与 Shadowsocks 入站尽量使用不同端口；不要给面板端口做 UDP 暴露。

## 代理数据面

### 目标地址限制

默认拒绝以下目标，防止把服务端当作内网跳板：

- 回环地址（127.0.0.0/8、::1）
- 私有地址（10/8、172.16/12、192.168/16、fc00::/7）
- 链路本地（169.254/16、fe80::/10）
- 组播、未指定地址、保留地址
- 云元数据地址：`169.254.169.254`、`100.100.100.200`、`fd00:ec2::254`

`security.allow_private_targets` / 面板「允许内网目标」可以放开内网访问，但**云元数据地址始终拒绝**。

域名目标会先解析，再在 `net.Dialer.Control` 中对最终 IP 二次校验，降低 DNS rebinding 风险。解析结果缓存 60 秒。

### 关联域名

入站的分享域名（`domain`）只用于渲染 `ss://` 链接与订阅，不参与监听、协议或 TLS。保存时会严格校验，拒绝以下值，避免生成客户端无法解析的链接：

- 含协议（`http://`）、端口（`example.com:8388`）、路径或方括号（`[::1]`）；
- 空标签（`a..b`）、以连字符开头或结尾的标签、非法字符；
- 带 zone 后缀的 IPv6（`fe80::1%en0`）、超过 253 字符的域名或超过 63 字符的标签。

同一套校验也用于系统设置里的 `public_host`。

### 认证与隔离

- SS2022 多用户：EIH 身份头由服务器 PSK 派生密钥加密，用户间无法互相冒充；错误 PSK 在握手阶段被拒绝。
- 被禁用（或删除）的用户不会进入协议用户表，因此其握手会直接失败，而不是先完成握手再在业务层断开；配额、到期与 IP 限制仍在连接建立时检查。
- 传统 AEAD 多用户：库在握手时逐个尝试用户密钥，失败即断开；用户数过多会增加 CPU 开销。
- 单用户方法（`2022-blake3-chacha20-poly1305`）不携带身份头，因此一个入站只能有一个启用用户，避免流量错记到别人名下。这条规则在**创建、更新、启停（toggle）、导入和改方法**五条路径上都执行；运行时另有一道兜底，配置不合法时拒绝启动该入站而不是静默只服务一人。`sspanel check` 会列出违反该规则的存量数据。

### 资源限制

| 项目 | 限制 |
|---|---|
| 每用户并发会话 | 4096（TCP 连接 + UDP NAT 会话） |
| 每 UDP 会话目标地址 | 256 个 |
| UDP 会话空闲超时 | 默认 60 秒 |
| 每 TCP 握手超时 | 30 秒 |
| 用户 IP 限制 | 可选，按不同来源 IP 数计 |

### 流量与配额

- 计数在内存中累加，每 10 秒落库；正常退出、配额越界、手动重置时立即落库（配额越界通过向后台 flush 循环投递一次立即落库请求完成，不阻塞数据面）。
- 配额越界立即断开该用户会话；到期/禁用由后台任务每 30 秒检查并关闭连接。
- 崩溃最多丢失一个落库周期（10 秒）的流量计数，不影响配置。

## Shadowsocks 2022 与时钟

SS2022 握手校验时间戳，允许 ±30 秒偏差。请确保：

```bash
timedatectl status          # 确认 System clock synchronized: yes
```

时钟不同步会导致所有 SS2022 连接失败（传统 AEAD 不受影响）。两步验证的 TOTP 同样依赖时钟：允许 ±1 个时间步（共 90 秒窗口）。

## 数据与备份

- 数据库包含：管理员密码哈希、会话签名密钥、TOTP 密钥（20 字节随机、base32，存于 `admins` 表）、恢复码哈希（仅 SHA-256，单次使用，存于 `admin_recovery_codes`）、入站服务器 PSK、用户 PSK、订阅 token、流量记录。
- `traffic_daily` 保存每用户每日明细，`traffic_daily_totals` 保存按天汇总（仅两个字节计数，不含任何标识或凭据），两者在同一事务内更新；`RebuildDailyTotals` 可从明细重建汇总。
- `audit_logs` 保存面板操作审计：时间、操作人、动作、对象、摘要与来源 IP，不含任何凭据。
- 数据库文件权限为 `0600`，数据目录 `0700`。程序在打开数据库时会把文件、`-wal` 与 `-shm` 收紧到 `0600`，创建数据目录时使用 `0700`（已存在的目录保持原样），并在创建任何文件前把 umask 设为 `0077`；`deploy/sspanel.service` 同样带 `UMask=0077`，`install.sh` 创建的目录为 `0700`。若目录是手工创建的且更宽松，请自行 `chmod 700`。`chmod` 失败（只读挂载、属主不符）只记录警告，不会阻止启动。
- 备份文件等同敏感数据，请加密存储并限制访问。数据库备份会一并包含 TOTP 密钥与恢复码哈希；恢复码明文只在启用或重生成时显示一次。
- 订阅 token 泄露后，在用户列表点「链接」→「重置订阅」即可作废旧链接（对应 `POST /clients/:id/token`，审计动作 `client.token`）。

## 已知边界

- 不防御服务端被入侵后的内存取证；PSK 在进程内以明文派生密钥。
- 不提供多管理员/RBAC；只有一个管理员账号。
- 不提供审计日志导出；HTTP 访问日志写入 stderr，由 systemd/journald 管理。订阅路径的 token 会被脱敏，但访问日志本身仍记录操作时间与来源 IP。
- 不做主动探测防护（如 TLS 伪装、流量整形）；Shadowsocks 本身不是抗主动探测协议。如需更强隐蔽性，请配合 CDN/反代或使用其他协议。
- 两步验证只在登录时增加一步，不能保护已经被劫持的会话；关闭/绑定与重生成恢复码要求输入当前密码，但没有更细的授权粒度。
- 没有「记住此设备」：每次登录都要求验证码或恢复码。
- 不支持 WebAuthn/Passkey。
- 不做按账号锁定（避免被用来做 DoS）；登录第二步与密码步共用按 IP 限流，面板仍应只经 SSH 隧道或 TLS 反代访问。
- 服务器时钟需 NTP 同步：TOTP 允许 ±1 个时间步（共 90 秒窗口），时钟漂移会导致验证码被拒。
- 传统 AEAD 的“多用户”依赖试解密，用户数很多时（数百以上）建议拆分成多个入站或改用 SS2022。
